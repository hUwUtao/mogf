# MOGF MVP

This runnable MVP reads a bounded subset of the `mogf.project` v1 document and evaluates exact composition frames in Rust. It traverses groups, samples composition-clock `curve.from_to` tracks, evaluates shared plane/box batches and shaped text, resolves unlit materials, composes XYZ transforms, and emits either a JSON `mogf.frame` snapshot or wgpu-rendered PPM frames. Text uses the bundled Noto Sans variable font, wraps at word boundaries, extracts glyph outlines and tessellates filled caps and side walls. Stable grapheme token IDs can be targeted individually; `word:<first-token-id>` selectors target each word. A `text.weight` track animates the font's `wght` axis, while selected words accept XYZ translation tracks.

```sh
cargo run -- --help
cargo run -- render --help
cargo run -- frame --help
cargo run -- examples/planar_scene.json
cargo run -- strip examples/planar_scene.json --count 12 --columns 4 -o renders/planar-strip.ppm
cargo run -- timeline examples/planar_scene.json
cargo run -- inspect examples/planar_scene.json
cargo run -- sample examples/planar_scene.json 30
cargo run -- --json measure-plane examples/camera_dolly_compare.json 90 5 --composition-id perspective
cargo run -- frame examples/planar_scene.json 30 -o renders/planar
cargo run -- --json render examples/mogf_intro.json 0 180 -o renders/intro
cargo run -- render examples/mogf_intro.json 0 180 --video renders/intro.mp4
cargo run -- render-audio examples/mogf_intro.json -o renders/intro-audio.wav
cargo run -- --json frame examples/text_kinetics.json 90 -o renders/text
cargo run -- --preview render examples/text_kinetics.json 0 180 renders/text-preview
cargo run -- lint examples/planar_scene.json
cargo run -- live examples/planar_scene.json
cargo run -- live examples/principled_pixelated.json --composition-id pixelated
cargo run -- live examples/planar_scene.json --msaa 4 --blend alpha --depth test-write --cull none
cargo run -- live examples/planar_scene.json --shader examples/shaders/tint.wgsl
cargo run -- edit examples/planar_scene.json
cargo run -- frame examples/planar_scene.json 30 60 -o renders/planar-frames
cargo run -- render examples/planar_scene.json 0 120 renders/planar
cargo run -- render examples/parallax_stack.json 0 120 renders/parallax
cargo run -- render examples/kinetic_sweep.json 0 120 renders/sweep
cargo run -- sample examples/text_kinetics.json 20
cargo run -- render examples/text_kinetics.json 0 180 renders/text_kinetics
cargo run -- render examples/camera_dolly_compare.json 0 180 renders/camera_dolly/perspective --composition-id perspective
cargo run -- render examples/camera_dolly_compare.json 0 180 renders/camera_dolly/orthographic --composition-id orthographic
```

`render` is the default command: `mogf-mvp project.json` renders the default composition, and `--composition-id ID` selects another. The default is `main`, or the only composition if `main` is absent; if several compositions exist without `main`, specify the ID. `render` accepts an end-exclusive frame range and writes `frame_0000.ppm` files to `-o/--output` (default `renders/`). `--video FILE.mp4` instead streams raw RGBA frames directly to FFmpeg and encodes H.264 MP4 without keeping a frame sequence; it requires `ffmpeg` with `libx264` on `PATH` and refuses to overwrite an existing output. The encoder uses the composition frame rate, CRF 18, and `yuv420p`, padding odd image sizes by at most one pixel for compatibility. `frame` renders selected frames into a directory; `strip` creates a labelled contact sheet from evenly spaced frames; `sample` prints the serialized frame snapshot. `timeline` lists composition clocks and frame counts, and `inspect` evaluates requested frames (or the first and last frames by default) without writing images. Interactive terminals show render progress on stderr; `--json` suppresses the progress bar. The camera comparison uses the same layered planar scene and Z dolly (10 to 5.5) in each composition. Perspective FOV follows the camera distance to keep the plane at Z=0 the same apparent size; the orthographic camera keeps a fixed scale and matches the perspective framing at the start.

`measure-plane` reports a camera-aligned virtual plane's visible width/height, world transform and world-units-per-pixel at a positive camera-space distance. Perspective plane dimensions scale linearly with distance; orthographic dimensions stay fixed. It samples the chosen frame, so animated camera motion and FOV are reflected. The plane is measurement data only and is not inserted into or drawn with the scene.

`render`, `frame`, and `strip` use the same wgpu scene renderer, including image planes, project shaders, lights, shadows, deformation and camera effects. One process-wide Vulkan device retains geometry, texture, pipeline and instance caches; the Vulkan pipeline cache is also persisted between runs when supported. Offscreen color, depth, MSAA and readback targets are reused at the current output size. GPU culling compacts instances into indirect draws. PPM readback is synchronous. Rendering requires a Vulkan adapter, which may be hardware or Mesa software Vulkan. Scene evaluation, text outlines and tessellation run on the CPU before GPU rendering.

`lint` reports JSON parse/schema failures with line and column, then checks scene support at the first and last frame of each composition. Add `--all-frames` to check every frame (up to 3000 per composition), `--composition-id main` to select one composition, or `--json` for diagnostics as JSON. `live` opens a wgpu-rendered window, plays the selected composition, and checks watched file metadata for edits. It shares the persistent GPU mesh cache, GPU camera-frustum culling, compacted instanced draws, configurable MSAA and depth path with `edit`. CPU frame preparation supplies conservative local bounds; a wgpu compute pass evaluates them against the camera frustum, compacts visible instances by draw batch, and writes indirect draw counts. Opaque meshes share batches; transparent instances keep authored order in one-instance batches. The culler rejects only when all eight transformed corners are outside one frustum plane. Its overlay reports UI update rate and CPU frame-preparation time; `--stats` also prints per-second sample, scene-packet and GPU-preparation timings with mesh hits/uploads. Polling compares file sizes/modification times instead of rereading every asset each interval; changed saves still trigger a full reload. Valid saves are rehydrated into the existing live session at the corresponding project time; unchanged object, graph, material, asset and other table records are retained, while changed records are replaced. If a save is malformed or unsupported, the last valid frame stays visible and the window title and terminal show the diagnostic. Press Space to pause/play, Left/Right to step while paused, R to reload immediately, and Escape to close.

`edit` opens a compact timeline workbench. The composition ID is optional: it defaults to `main`, or to the only composition in the file. The top strip switches compositions, controls playback, and scrubs frames; the full-width timeline scrolls through animation tracks and selects their target objects. Press Space to play or pause, and Left/Right to step frames while paused. `Data` opens object/frame JSON and lint details on demand. The editor watches the root and imported files, rehydrates changed records, and surfaces parse, import, and evaluation errors. It checks the first and last frame of every composition on reload. Launch it with `mogf-mvp edit examples/planar_scene.json` or pass a composition ID to choose the initial view. The preview uses a persistent wgpu surface renderer with configurable MSAA and depth. A compute pass on the GPU culls planes, boxes, and glyphs whose conservative transformed bounds lie wholly outside a camera-frustum plane, compacts visible instances, and produces indirect draw counts. Planes and boxes share unit meshes, with authored size applied per instance; glyph meshes reuse GPU buffers on cache hits within a 256 MiB budget that accounts for geometry and glyph cache keys. Equal opaque meshes share instanced indirect draws, while camera and source instance buffers update only when their bytes change. Shaped text also reuses a bounded CPU geometry cache keyed by font metadata and all shaping parameters, including animated weight. Cache misses for glyph topology still run on the CPU, and transparent draws retain authored order. Offline export uses this same renderer.

Both `live` and `edit` accept `--msaa 1|4`, `--blend alpha|replace`, `--depth test-write|test-only|disabled`, and `--cull none|front|back`. The sample counts use portable surface-format support; requesting unsupported counts fails before opening a window. `--shader path.wgsl` loads a user WGSL surface function at launch; the file defines `fn mogf_surface(input: VertexOut) -> vec4<f32>`. It receives clip-space position and the default linear shaded/tinted color, then returns linear RGBA. Naga validates the function in the renderer's shader module before opening the window. This hook customizes fragment color while keeping the renderer's vertex transform and resource bindings fixed; changing the shader file requires relaunching the app. These launch settings affect live/edit. Offline export uses 4x MSAA, alpha blending, depth testing/writes, and no face culling; project-authored materials, shaders, and effects are shared.

Project materials can bind imported user surface programs through `materials.<id>.params.shader`; shader records reference `kind: "shader"` assets and use `stage: "surface"` or `stage: "surface_scene"`. Both receive the material's `shader_params` and `VertexOut.receives_shadow`; they may call `mogf_default_lit_surface(input)` to retain built-in lighting, or use `mogf_surface_shadow_visibility(input)` plus the public light helpers for a custom response. `surface_scene` additionally exposes `mogf_scene_color(input, offset_uv)`, a linear sample from this frame's opaque scene buffer. The renderer draws opaque batches, snapshots the resolved buffer once, then draws transparent batches; all scene-reading materials share that snapshot, so they do not see one another or earlier transparent draws. This path adds one scene-color copy and temporary texture only when a `surface_scene` material is used. The lower-level `mogf_shadow_visibility(world_position)` explicitly bypasses the material receive flag. Materials independently set `casts_shadow` and `receives_shadow` (both default true). Non-casting instances are omitted from GPU shadow culling; the fitted shadow camera covers caster and receiver bounds. Shader files resolve relative to their declaring project/import, are validated against the WGSL renderer ABI, and get cached per material program. `--shader` remains the session-wide fallback. A native layer can list up to eight project-authored camera effects in `effects`; each resolves to a `stage: "camera_effect"` WGSL asset, samples the prior full-view buffer and runs in order without CPU readback. A layer can also select a `stage: "vertex"` asset with `vertex_shader`; it defines `mogf_deform(position, shader_params) -> vec3<f32>` in local space, before camera and light transforms, so its displaced shape is used in both the visible render and shadow map. Since the WGSL ABI does not declare a displacement bound, frustum culling is bypassed for those instances, and large deformations can exceed the fitted shadow-camera margin. Surface normals are derived from deformed view-position derivatives. `--vertex-shader` remains the separate launch-time post-projection hook, and `--effect-shader` remains a session fallback. `examples/principled_plastic.json` demonstrates a receiving/non-casting Principled floor, a custom diffuse blocker, and a user-authored Fresnel/ripple glass surface that samples and offsets the opaque scene buffer, receives shadows, and returns custom shadow opacity. `examples/principled_pixelated.json` imports that scene and exercises project-authored vertex deformation and an ordered pixelation/color-grade chain.

The forward lighting path accepts up to eight ambient, directional, point, or spot lights. A spot points along its object's local -Z axis; `inner_angle` and `outer_angle` are half-cone angles in radians, with a smooth transition between them and `outer_angle < pi/2`. Point and spot lights share distance and range falloff. One directional or spot project light may set `"casts_shadow": true`; directional shadows use a fitted orthographic map and spot shadows use a perspective map. `shadow_resolution` selects 128, 256, or 512 square texels (default 512); lower sizes reduce depth and transmittance attachment storage and shadow raster work. The alpha-transmittance map uses single-channel R8 storage. `shadow_bias` controls normalized light-depth bias (0–0.05), while `shadow_filter_radius` controls the PCF footprint in shadow-map texels (0 selects one hard comparison sample, 0–8 selects the four-tap filter). Defaults are 0.0012 bias and 0.5 texel radius. The same filter taps sample alpha transmittance, smoothing transparent caster edges. Principled and Phong surfaces receive the resulting shadow through that light unless their material opts out; unlit surfaces stay unlit. Materials independently control casting and receiving. The preview supports one fitted directional or spot shadow map with configurable resolution, PCF, and an alpha-transmittance pass. Ordinary opaque casters write depth; transparent instances and custom WGSL materials use the alpha pass, where `mogf_surface(input).a` sets per-pixel shadow opacity unless a cheaper `mogf_shadow_opacity(input)` hook is provided. This preserves opacity authored by custom surface code instead of flattening it into opaque depth. The pass multiplies transmittance while testing against ordinary opaque depth. Shadow maps are cached by caster geometry, transform, deformation, opacity, shader source, and fitted light camera, so camera-only motion reuses the maps. The Principled plastic example includes a translucent orange blocker and blue spot shadow key. Point-light shadows, transparent-to-transparent scene refraction, per-mesh intermediate effects, and a general multi-pass resource graph remain unimplemented. The plastic recipe does not need a special material operation.

Both interactive windows explicitly select wgpu's Vulkan backend and high-performance adapter preference; startup prints the chosen Vulkan adapter. They fail at startup if eframe does not provide a Vulkan render state. Offline `render`, `frame`, and `strip` use the same Vulkan wgpu renderer.

The MVP loader also composes whole project files through an optional top-level `imports` list:

```json
"imports": [
  { "uri": "../shared/materials.json" },
  { "uri": "../shared/shapes.json" }
]
```

Import paths are relative to the file that declares them. Imports resolve recursively, cycles fail, repeated paths load once, and records merge by table. IDs remain global within each table, so duplicates fail with the table and ID in the diagnostic. The root file supplies the project ID; imported compositions appear in `timeline` and can be sampled by ID. Assets resolve relative to the file that declares each asset. The live view watches imported project files and existing assets too. This is an MVP loader extension; the submitted proposal/schema snapshots have not been revised to include it.

## Example projects

- [Planar scene](examples/planar_scene.json) and [parallax stack](examples/parallax_stack.json): authored planes, transforms, groups, and depth.
- [Kinetic sweep](examples/kinetic_sweep.json) and [text kinetics](examples/text_kinetics.json): animated shapes, words, and glyph instances.
- [MOGF intro](examples/mogf_intro.json): editable native scene with camera motion and materials.
- [Animated score](examples/animated_score.json), [first verse](examples/twinkle_first_verse.json), and [phrase focus](examples/twinkle_phrase_focus.json): planar music notation and text in 3D scenes.
- [Camera dolly comparison](examples/camera_dolly_compare.json), [Principled plastic](examples/principled_plastic.json), and [pixelated Principled material](examples/principled_pixelated.json): camera, lighting, and shader examples.

Render outputs are written locally to `renders/` and are not part of the source tree.

Unsupported document features fail explicitly. The current slice accepts font, PNG image, WAV audio and WGSL shader assets, empty state/functions/clips/media/recordings/bakes, unlit/Phong/Principled materials, optional per-material surface programs, and up to eight ordered imported camera effects on a native 3D layer. Preview and export execute the same shader programs. It also supports perspective or orthographic 3D layers, plane/box batches, planar shaped text, object translation, text-weight and camera FOV tracks (including distance-based dolly zoom), and instance translation/rotation/opacity tracks. Quaternion tracks declare their `quaternion_xyzw` unit and spin winding. Rustybuzz shapes runs; Unicode segmentation supplies grapheme IDs and MVP word-boundary wrapping; ttf-parser extracts variable glyph outlines; lyon tessellates filled glyph caps; wgpu draws the extruded triangles with a depth buffer. General bidi/fallback, Unicode line-break policy, boolean cleanup of intersecting contours, GPU extrusion, automatic sprite billboarding, data-function evaluation, and general media/clip decoding remain unsupported. The font files and their SIL Open Font License are in `examples/assets/fonts/`.

`mogf.geometry.plane` is a local MVP operation added to exercise the proposal's planar-first scene direction; it is not yet registered in the submitted descriptor catalog. Transparency remains in authored order. Material IDs resolve to unlit, Phong, or Principled parameters and may select an imported user surface program.

The serialized format and constraints remain proposal material. This MVP is evidence for a small Rust loading/evaluation path, not full schema, robust font/layout preparation, the proposed GPU mesher, or reference-example conformance.

PNG planes use an ordinary `mogf.material.unlit` material with `params.image` naming a `kind: "image"` asset. Pixel data is decoded at load (4096 pixels per side, 128 MiB total decoded project pixels), uploaded as sRGB textures and cached by content. UVs follow local XY; optional `params.image_uv_rect: [u_min, v_min, u_max, v_max]` selects a normalized image window (default `[0, 0, 1, 1]`). Alpha uses authored draw order, and image planes can cast alpha-shaped shadows. Image materials currently cannot combine with custom surface shaders or lit materials. No billboard behavior is implicit. A composition audio list accepts legacy asset IDs and scheduled clips such as `{"asset":"music","start":2.5,"source_start":1.0,"duration":8.0,"gain":0.7,"channel":"dialogue"}`. Named `audio_buses` provide bus gain and pan; clips can overlap and route to the implicit `main` bus or a declared bus. The offline DSP pipe is WAV decode → trim/resample → clip gain → bus summing → bus gain/pan → master clamp. Live/edit and `render-audio` share this stereo mixer. `render-audio` writes stereo 16-bit PCM WAV for the composition duration (up to 10 minutes), and `render --video` muxes the matching audio range as AAC alongside H.264 video. The processor-chain seam is ready for offline effects or a future VST adapter, but effects and plugin hosting are not implemented.
